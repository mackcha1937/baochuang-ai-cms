## 4. 正向路径

- 图片文案已确认且视觉状态为 `draft` 时，提交创建不可变 V1 和待开始产品审核任务；撤回后保持内容与视觉并恢复编辑。
- 同一图片重新提交创建不可变 V2；审核详情同时显示来源产品、提交内容、版本号、提交人和时间。
- 产品审核开始、通过后原任务锁定，并原子创建待开始合规审核任务；合规开始、通过后内容状态变为 `approved`。
- 文章公众号与小红书分支拥有独立 `reviewStatus`；公众号审核中时，小红书仍可确认全文和继续创作。
- 培训讲稿完整确认后可提交；章节、讲稿、知识卡、3 道题及来源进入同一不可变内容包。
- 工作台待审数量从 `review_tasks` 实时统计；任务列表支持阶段和状态筛选。

## 5. 反向路径

- 图片缺少确认文案或可用视觉、文章未确认框架/全文、培训章节或题目结构不完整时返回 `422 / CONTENT_REVIEW_INCOMPLETE`。
- 文章不指定渠道、非文章错误指定渠道返回 `422 / REVIEW_TARGET_INVALID`。
- 有运行中生成任务时返回 `409 / CONTENT_JOBS_ACTIVE`；已提交版本的生成、人工编辑、确认、解锁、图片布局和替换图均被服务端锁定。
- 空驳回原因在前端直接阻止，服务端绕过请求返回 `422 / REVIEW_REASON_REQUIRED`。
- 过期修订返回 `409 / REVISION_CONFLICT`；已开始任务撤回返回 `409 / REVIEW_WITHDRAW_FORBIDDEN`。
- 已处理任务使用不同幂等键再次决定返回 `409 / REVIEW_STATE_CONFLICT`；同一幂等键重放返回原结果。
- 只读用户提交或查看审核中心返回 `403 / PERMISSION_DENIED`，并记录权限拒绝审计。

## 6. 异常恢复

- 提交和审核决定使用服务端幂等键；提交键按内容和渠道隔离，不同内容复用同一客户端键不会串用任务。
- 前端在“提交响应成功但详情刷新失败”时保留原幂等键，用户重试仍可安全取得原任务。
- 产品通过与合规任务创建处于同一 SQLite 事务；失败不会留下通过但无下一任务的半状态。
- 驳回后原版本和决定记录不变；返回修改只创建新内容修订，重新提交生成递增版本号。
- 未开始撤回保留版本和 `cancelled` 任务作为历史，不删除审计证据。

## 7. 权限与审计

- `content.submit` 控制提交/撤回，`content.edit` 控制驳回后返回修改。
- `review.product` 与 `review.compliance` 分别控制对应阶段详情、开始和决定；列表按角色可见阶段过滤。
- 审计包含 `content.submit`、`content.review.withdraw`、`content.review.reopen`、`review.product.start/approve/reject`、`review.compliance.start/approve/reject` 和 `permission.denied`。
- 审核人不直接修改提交正文；任务、记录和审计均无删除/覆盖接口。

## 8. 安全

- 不可变快照只包含内容、渠道、来源产品和设置，不包含数据库路径、存储路径、供应商任务私有字段或 API Key。
