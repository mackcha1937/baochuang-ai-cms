## 5. 正向路径

- 图片文案：从已确认产品创建草稿；任务成功结果包含标题、卖点、区块与免责声明；支持重新生成、人工 JSON 兜底和人工确认。
- 文章：公众号与小红书生成独立框架；框架确认后只解锁对应渠道全文；模拟供应商成功生成全文。
- 培训：课程框架生成/人工填写 → 人工确认 → 讲稿解锁 → 讲稿与知识卡、恰好 3 道单选题 → 人工确认。
- 统一任务：创建时强制幂等键；记录 `queued/running/succeeded/failed/cancelled`、输入快照、输出、公开错误、错误码、attempt、provider、model。
- 人工兜底：图片、文章框架/全文、培训框架/讲稿均可保存经结构校验的人工内容。
- 真实供应商：图片文案在失败任务上重试成功并确认；公众号、小红书框架分别生成且互不覆盖，公众号全文生成成功；培训框架、讲稿和 3 道题依序生成并确认。

## 6. 反向路径

- 无已确认产品且人工素材为空时拒绝创建；未确认产品拒绝用于创作。
- 不匹配的项目类型/任务类型、文章任务缺少渠道分支、无效幂等键、缺失资源均返回稳定错误。
- 文章全文和培训讲稿在框架未确认时拒绝创建任务或保存人工结果。
- 结构化输出字段缺失、字段类型错误、培训题目不等于 3 道时拒绝落库。
- 确认后的文章框架、培训框架/讲稿禁止新建任务、人工覆盖及重试旧任务，返回 `CONTENT_NODE_LOCKED`。
- Viewer 演示用户创建内容返回 403；超级演示用户权限保持正常。

## 7. 异常恢复

- DeepSeek Key 缺失时任务进入 `failed`，错误为“已保留全部输入”；刷新和服务重启后草稿、失败任务和输入快照仍存在。
- 超时、连接失败、429、401/403、5xx 均映射为不泄露服务端信息的公开错误码；空输出、非法 JSON 或无依据数字最多执行 3 次受限修正，仍失败则保存为可重试状态。
- 取消后的任务保留输入，可重试且 attempt 递增；单渠道失败不影响另一渠道。
- AI 不可用时可人工粘贴结构化内容继续确认；浏览器已实际完成图片、文章框架和培训全链路人工兜底。
- 真实培训讲稿首次出现无依据数字时未确认，任务以 `AI_OUTPUT_UNGROUNDED` 安全失败；修复后从同一持久化任务重试，最新输出通过校验再确认。

## 8. 权限与审计

- 审计详情只包含对象、任务和公开错误码，不记录 Authorization、API Key 或完整敏感请求头。

## 9. 安全

- DeepSeek Key 只从服务端 `DEEPSEEK_API_KEY` 读取；前端只读取 `deepseekConfigured` 布尔状态。
- DeepSeek 请求使用服务端 Authorization 请求头；请求正文、数据库任务快照、API 响应和公开错误不含 Key。
- DeepSeek 输出在落库前执行任务级严格结构校验、数组数量和字符串类型/长度检查。
- 所有阿拉伯数字和百分比必须存在于产品快照、人工设置、明确指令或已确认上游内容的白名单；不满足时输出不得覆盖当前内容。
- 项目类型、任务类型和渠道分支做服务端关联校验；确认节点同时实施 UI 与 API 锁定，防止绕过前端覆盖。
- `.env`、`data/*.db`、上传文件由 `.gitignore` 排除；凭据扫描零命中；npm 生产依赖漏洞审计为 0。

## 12. 失败与修复记录

1. 浏览器人工编辑器首次未发保存请求：确认是折叠详情内辅助鼠标点击未触发 React；用原生输入/DOM 点击复核接口成功，并补自动化人工保存测试与编辑器持久化同步。
2. 人工保存测试曾依赖文本唯一性、空格排版和 effect 到达时序：改为分别锁定预览区域并解析 textarea JSON；每次修改后全量重跑。
3. 浏览器发现前置条件未满足或节点已确认时 textarea 仍可输入：同步禁用编辑器和保存按钮，新增培训门禁测试。
4. 培训框架确认后讲稿已解锁但徽标仍显示 `locked`：后端显式写入 `scriptStatus=empty`，前端为旧数据增加兼容回退。
5. 浏览器发现培训讲稿确认后仍可编辑，文章历史失败任务仍显示无效重试：增加前后端节点锁、历史任务归档和 409 回归测试。
6. 锁定回归首次发现查询字段遗漏导致内部异常：`save_manual_output` 改为读取完整内容行；随后全量回归通过。
7. `npm audit` 首次因沙箱 DNS `ENOTFOUND` 失败：按规则联网重跑，最终 0 漏洞。
8. 凭据扫描曾命中测试假 Bearer 字符串：重写断言消除误报，最终扫描零命中。
9. 真实图片文案首次返回 `AI_OUTPUT_INVALID`：定位为提示词只描述字段、未给出精确嵌套 JSON；补充任务级精确模板与结构纠错上下文，全量复测后原失败任务重试成功。
10. 真实培训讲稿虽满足 JSON 结构，却生成产品资料中不存在的疾病数量、比例和年龄：未确认该输出；增加数字来源白名单、落库前依据校验和 `AI_OUTPUT_UNGROUNDED`，新增正反向测试并全量重跑。
11. 仅提示白名单仍可能在修正时产生新数字：将上一份非法 JSON 和精确违规值加入修正上下文，将供应商修正限制为最多 3 次；培训讲稿在仍不合格时执行确定性安全修复，删除含无依据数字的片段、从已确认资料重建 3 道题，再次执行结构与依据校验后才落库。
12. 三次供应商修正可能超过前端原 60 秒等待窗口：AI 任务请求超时调整为 165 秒，服务端每次调用仍保持 45 秒上限；自动化测试、真实重试和完整回归均通过。
13. 最终真实培训重试在 attempt 5 成功，最新图片、双渠道文章、培训框架与讲稿均通过独立结构校验；随后确认讲稿并重启服务，内容、状态和锁定完整恢复。
