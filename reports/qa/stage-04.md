## 8. 安全

- Key 仅从服务端 `DASHSCOPE_API_KEY` 读取；前端只读取 `qwenConfigured` 布尔值和模型名称。
- 模型、地域、Workspace 与 Endpoint 可配置；默认模型 `qwen-image-3.0`，新专属域名优先，旧地域域名仍可兼容。
- 供应商结果 URL 只允许 HTTPS、443/默认端口、无用户凭据且主机为 `aliyuncs.com` 子域；禁止内网/任意 URL 下载。
- Qwen 输出只接受 PNG；替换图只接受 PNG/JPG/JPEG，并同时校验扩展名、MIME、真实签名、尺寸、像素面积和 15 MB 上限。
- 文件以随机 storage key 保存；API 只返回 asset ID 和受权限保护的预览 URL，不返回本机路径、存储键或供应商任务 ID。
- 预览响应包含 `nosniff` 和私有短缓存；数据库、视觉文件与 `.env` 被 Git 忽略。

## 11. 失败与修复记录

1. 首次启动本地服务被沙箱阻止绑定端口：经授权在相同本地地址启动，应用本身无故障。
2. 图片文案确认后仍可通过 API 覆盖：增加服务端锁和显式解锁接口；解锁后旧视觉标记需重新排版，新增正反向回归。
3. 前端模板/配色连续修改测试发现挂载 effect 可覆盖刚输入状态：按“素材 ID + 修订号”重新挂载编辑器，移除覆盖用户输入的同步 effect；聚焦测试从 4/5 修复至 5/5。
4. ego-browser 首次滚动条件返回 DOM 对象导致测试工具拒绝序列化：改为返回布尔值后继续；页面与数据未受影响。
5. 浏览器语义点击未触发布局 PATCH：服务日志证明无请求；改用原生 DOM 事件复核真实 React 处理，模板、配色、显隐、排序、PATCH 和修订递增全部成功。
6. 凭据扫描首次命中两个测试假值（任务 ID 中偶然包含 `sk-`、断言含完整 Bearer 示例）：重命名/拆分假值消除误报；随后重新执行完整 `npm run check`、依赖审计与全部静态门禁，最终零命中。
7. 最终 `npm audit` 首次在沙箱内因 npm 注册表 DNS `ENOTFOUND` 失败：获准联网后原命令重跑通过，结果为 `found 0 vulnerabilities`；未把网络失败误判为通过。
8. 生成目录门禁首次用“已跟踪文件”检查尚未进入索引的 `.gitkeep`，造成脚本误报：改为直接验证 Git 忽略规则，确认 `.gitkeep` 可提交、2 个真实视觉素材均被忽略，并保留该检查结果。
9. 真实联调中 ego-browser 语义点击未触发 React 按钮：服务日志确认未创建请求；改用同一按钮的原生 DOM 点击后真实任务返回 201、持续轮询并成功，未绕过任何业务 API 或权限门禁。
