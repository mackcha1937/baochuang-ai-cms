# 保创AI分阶段开发与验收流程

## 1. 固定流程

每个阶段严格执行以下顺序：

1. 冻结本阶段范围和不做事项。
2. 明确验收标准、测试数据和风险点。
3. 在独立 `stage/NN-short-name` 分支开发。
4. 执行代码检查、自动化测试、接口测试、页面与按钮闭环测试、安全检查和回归测试。
5. 记录测试环境、测试项、实际结果、失败修复和遗留风险。
6. 全量复测通过后提交并保留阶段分支。
7. 得到阶段验收结论后，才能从该提交创建下一阶段分支。

## 2. 每阶段最低自检范围

| 检查域 | 必须覆盖 |
| --- | --- |
| 功能 | 正常输入、边界输入、空输入、重复操作、刷新后状态 |
| 交互 | 保存、取消、返回、关闭、未保存提醒、禁用态、加载态 |
| 异常 | 网络失败、AI超时、限流、解析失败、重试、取消任务 |
| 数据 | 新增、编辑、版本、删除/失效、重启后持久化、并发冲突 |
| 权限 | 有权限、无权限、多角色叠加、越权接口、审计记录 |
| 安全 | 密钥不进前端/仓库/日志，上传类型、大小、文件名与路径校验 |
| 兼容 | PC常用分辨率、Chrome/Edge，中文、长文、长表格 |
| 回归 | 当前阶段全部功能与历史已验收阶段的关键路径 |

任何一项失败，本阶段状态保持“未通过”。修复后必须重新执行全量自检。

## 3. 验收记录

阶段验收记录保存在 `reports/qa/stage-NN.md`，至少包含：

- 分支名与提交号
- 本阶段范围和不做事项
- 自动化命令及结果
- 页面/接口测试清单
- 正向、反向与异常测试证据
- 已修复问题
- 遗留风险（如有）
- 最终结论：通过或未通过

## 4. 分支示例

```text
main
└── stage/00-preparation
    └── stage/01-foundation
        └── stage/02-product-library
            └── stage/03-ai-content
```

分支名称仅为示例。实际阶段由需求拆分后确定。

## 5. 用户操作边界

以下操作交给项目负责人完成：

- 填写 DeepSeek、阿里云百炼/千问、火山引擎等真实密钥
- 真实账号登录、实名、充值、服务开通和授权
- 域名购买、备案以及需要短信/扫码确认的操作
- 正式环境最终发布确认

开发代理负责提供清晰的操作位置、变量名、验证方法，并在用户完成后继续自动检查。

## 6. 火山引擎上线预留

本地演示版先保证可运行与可展示，正式上线时优先考虑：

- 应用运行：火山引擎 ECS 或容器服务
- 数据库：托管 PostgreSQL
- 文件：TOS 对象存储
- 缓存与任务：Redis 及独立任务进程
- 域名与入口：备案域名、HTTPS、负载均衡或网关
- 运维：日志服务、告警、备份、密钥托管、调用成本监控

具体产品选型、区域和规格在上线阶段根据预算与并发量确定，不在本地阶段提前锁死。
